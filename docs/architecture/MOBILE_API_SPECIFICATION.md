# CTU-G Workspace Mobile API Specification

> **Phase 3 · Date:** 2026-11-12  
> **Status:** Existing contracts inspected; mobile use is PROPOSED and untested  
> **Evidence basis:** Read-only backend and web-client source inspection  
> **Proposed items are not implemented.**

## Status and scope

The contracts below describe source-routed endpoints, not runtime-verified
service behavior. They are browser-oriented today. No new endpoint is proposed
for the recommended session+CSRF spike. Mobile use requires the SRS governance
decision and a separately approved spike.

Contract terms:

- **EXISTING** means included by `backend/config/urls.py` and
  `backend/apps/accounts/urls.py`.
- Request methods list the view's allowed methods; safe endpoints also permit
  HEAD/OPTIONS and mutation endpoints permit OPTIONS.
- Bodies and sample identifiers are placeholders, not real account data.

## Existing endpoint contracts

### CSRF bootstrap

```text
Endpoint name: CSRF bootstrap
Status: EXISTING
HTTP method: GET (HEAD, OPTIONS also allowed)
URL: /api/v1/auth/csrf/
Authentication required: No; AllowAny
Permission required: None
Request headers: Accept: application/json (optional); no credentials required
Request body: None
Successful response: 200; {"csrfToken": "<masked-token>"}
Error responses: 405/406/415 are normalized by PublicJSONView; no normal body validation
Validation rules: GET only for the view; token generated by Django get_token()
Database effects: None expected by the view
Security considerations: CSRF middleware sets/updates csrftoken cookie; never log or publish the token
```

### Public registration

```text
Endpoint name: Registration request
Status: EXISTING
HTTP method: POST (OPTIONS also allowed)
URL: /api/v1/auth/register/
Authentication required: No; AllowAny, but explicit CSRFCheck is required
Permission required: None; request is limited to a registration request
Request headers: Content-Type: application/json; X-CSRFToken: current token
Request body: school_id (required string, 1–7 digits); email (required string/email, max 150);
  first_name (required string, max 100); middle_name (optional string, max 100, blank allowed);
  last_name (required string, max 100); suffix (optional string, max 20, blank allowed);
  requested_role (required Student or Instructor); password and password_confirmation
  (required strings, max 128, exact match)
Successful response: 202; {"message": "Registration request received. Eligible new accounts are pending administrative review."}
Error responses: 400 {error:{code:"validation_error",message,fields?}};
  403 csrf_failed; 405 method_not_allowed; 406 not_acceptable;
  415 unsupported_media_type; 429 throttled; 503 registration_unavailable
Validation rules: JSON object only; reject unknown/duplicate keys and non-finite constants;
  body limit 16,384 bytes; password validators; only Student/Instructor may be requested
Database effects: Atomically creates Pending/inactive Account and linked UserProfile with no role assignment;
  duplicate School ID gets the same public acknowledgement; email is not verified
Security considerations: CSRF is checked before parse/validation; throttled 5/min and 30/day by REMOTE_ADDR;
  no session or role is issued
```

### Login

```text
Endpoint name: Workspace login
Status: EXISTING
HTTP method: POST (OPTIONS also allowed)
URL: /api/v1/auth/login/
Authentication required: No prior authentication; AllowAny plus explicit CSRFCheck
Permission required: None
Request headers: Content-Type: application/json; X-CSRFToken: current token
Request body: {"school_id":"12345","password":"<placeholder>"};
  school_id required string max 50 with whitespace trimming; password required string
  max 256, whitespace preserved
Successful response: 200; {"authenticated":true,"account":{"school_id":"12345","roles":["<role>"]},"permissions":["<code>"]}
Error responses: 400 invalid_request; 401 invalid_credentials; 403 csrf_failed;
  405 method_not_allowed; 406 not_acceptable; 415 unsupported_media_type;
  429 too_many_attempts; unexpected in-view error 503 auth_unavailable
Validation rules: JSON object only; only school_id/password; active approved account,
  not framework staff/superuser, with at least one active assigned role
Database effects: Creates/rotates a Django session; no role or permission grants
Security considerations: One generic 401 for incorrect password, unknown ID, Pending,
  Rejected, inactive, framework-admin, or roleless users; throttled 8/min and 40/hour
```

### Logout

```text
Endpoint name: Workspace logout
Status: EXISTING
HTTP method: POST (OPTIONS also allowed)
URL: /api/v1/auth/logout/
Authentication required: No DRF auth class; the caller's session cookie is the session to clear;
  explicit CSRFCheck is required
Permission required: None
Request headers: Content-Type: application/json; X-CSRFToken: current token
Request body: {}
Successful response: 200; {"authenticated":false}
Error responses: 400 invalid_request; 403 csrf_failed; 405 method_not_allowed;
  406 not_acceptable; 415 unsupported_media_type; unexpected in-view error 503 auth_unavailable
Validation rules: Empty JSON object is the web client's request; CSRF must pass
Database effects: Django logout clears the caller's session
Security considerations: A CSRF-verified caller can discard its own session even if no longer eligible
```

### Current session / user permission hints

```text
Endpoint name: Current session
Status: EXISTING
HTTP method: GET (HEAD and OPTIONS also allowed)
URL: /api/v1/auth/session/
Authentication required: No DRF authentication class; reads Django session directly
Permission required: None
Request headers: Cookie: sessionid=<cookie> when a session exists; Accept: application/json
Request body: None
Successful response: Always 200 from the view:
  {"authenticated":false}, or
  {"authenticated":true,"account":{"school_id":"12345","roles":["<role>"]},"permissions":["<code>"]}
Error responses: GET path does not run CSRF; 405/406/415 are handled by WorkspaceSessionAPI;
  unexpected in-view error 503 auth_unavailable
Validation rules: Session identity must remain active, approved, non-framework-admin,
  and assigned at least one active role
Database effects: Read-only by view contract; database reads may occur
Security considerations: permissions are point-in-time UI hints only; protected actions must reauthorize server-side
```

### Forgot password

```text
Endpoint name: Password reset request
Status: EXISTING
HTTP method: POST (OPTIONS also allowed)
URL: /api/v1/auth/forgot-password/
Authentication required: No prior authentication; feature gate and CSRF required
Permission required: None
Request headers: Content-Type: application/json; X-CSRFToken: current token
Request body: {"school_id":"12345","email":"<placeholder@example.invalid>"};
  school_id required string max 50 with whitespace trimming; email required EmailField max 150
Successful response: 202; {"message":"If the account details match an eligible account, a password reset email will be sent."}
Error responses: 400 invalid_request; 403 csrf_failed; 405 method_not_allowed;
  406 not_acceptable; 415 unsupported_media_type; 429 too_many_attempts;
  503 recovery_disabled or auth_unavailable
Validation rules: Exact field set; recovery must be enabled; account must be approved, active,
  non-framework-admin and have an active role
Database effects: Read-only account lookup; attempts email delivery when eligible
Security considerations: Neutral response; throttled 4/min and 20/day; link targets web frontend;
  feature is disabled by default
```

### Reset password

```text
Endpoint name: Password reset confirmation
Status: EXISTING
HTTP method: POST (OPTIONS also allowed)
URL: /api/v1/auth/reset-password/
Authentication required: No prior session required; feature gate, CSRF, UID and token required
Permission required: None
Request headers: Content-Type: application/json; X-CSRFToken: current token
Request body: {"uid":"<encoded-id>","token":"<token>","password":"<placeholder>",
  "password_confirmation":"<placeholder>"}; exact required fields; password max 128
Successful response: 200; {"message":"Password changed. You can now sign in."}
Error responses: 400 invalid_request; 403 csrf_failed; 405 method_not_allowed;
  406 not_acceptable; 415 unsupported_media_type; 429 too_many_attempts;
  503 recovery_disabled, recovery_unavailable, or auth_unavailable
Validation rules: UID must decode to decimal account ID; valid unexpired token; account eligibility rechecked;
  matching passwords; Django password validators
Database effects: Locks eligible account and saves a new password hash in a transaction
Security considerations: 1800-second token; password change invalidates token;
  token is delivered through a web reset URL fragment; feature disabled by default
```

## Validation differences

| Endpoint | School ID validator |
|---|---|
| Registration | Required string, max 7, no trimming, then `[0-9]{1,7}` |
| Login | Required string, max 50, trim whitespace; no digits-only rule |
| Forgot password | Required string, max 50, trim whitespace; no digits-only rule; matched with email |

## Error and response shape limitations

In-view exceptions in the public/session API base classes are normalized to an
`error` envelope. Successful responses differ by endpoint. Django-level
unknown-route debug 404s and failures outside view handling can be HTML because
the current settings use `DEBUG=True`; clients must not assume JSON for every
failure. `GET /session/` returns `authenticated:false` rather than 401.

## Proposed endpoints

**No new endpoints proposed.** The recommended conditional spike uses the
existing endpoints above. Any future endpoint must be labeled **PROPOSED**,
have a separately approved contract, and must not be inferred from catalogue
entries or module names.
